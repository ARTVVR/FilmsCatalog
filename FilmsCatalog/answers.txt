1. Event Propagation (распространение событий) в JavaScript
-----------------------------------------------------------
Общее:
Event propagation — это механизм, по которому событие, возникшее на DOM-элементе, проходит через дерево DOM и может быть перехвачено или обработано на разных уровнях. Есть две классические модели: W3C (современная) — с фазами capturing, target, bubbling; и устаревшая модель IE.

Фазы:
1) Capturing (фаза захвата) — событие идёт сверху вниз: от корня документа (window/document/html/body ...) к целевому элементу (target). Обработчики, зарегистрированные с опцией { capture: true } будут вызваны в этой фазе.
2) Target (цель) — событие достигло целевого элемента. Обработчики на целевом элементе вызываются как для capture, так и для bubbling (в зависимости от регистрации).
3) Bubbling (всплытие) — событие идёт снизу вверх: от целевого элемента вверх по предкам до document и window. Обработчики, зарегистрированные без capture (по умолчанию), выполняются в этой фазе.

Практическое применение знаний о фазах:
- Делегирование событий: навесить обработчик на общего родителя (например, ul) и поймать клики на дочерних элементах. Экономит память и упрощает динамическую вставку элементов.
- Предотвращение нежелательных эффектов: различать, когда нужно перехватить событие до целевого элемента (capture) или после (bubble).
- stopPropagation / stopImmediatePropagation: останавливают дальнейшее распространение события. Используются для предотвращения выполнения других обработчиков.
- preventDefault: предотвращает действие браузера по умолчанию (например, переход по ссылке).
- Сложные интерфейсы: например, при реализации модального окна можно в capture-обработчике отсекать клики по фону до того, как дочерние элементы их увидят.
- Обработка form/submit: иногда выгодно слушать на capture, чтобы ранние валидации перехватывали событие до передачи его другим слушателям.

Особенности:
- Не все события всплывают (например, focus/blur традиционно не всплывают; их аналоги focusin/focusout — всплывают).
- Порядок вызова: capture-обработчики от корня к цели, затем обработчики на цели, затем bubble-обработчики от цели вверх.

Пример:
element.addEventListener('click', handler, { capture: true }); // обработчик в фазе capture
element.addEventListener('click', handler); // обработчик в фазе bubble

2. Promise в JavaScript, состояния, альтернативы, Event Loop
----------------------------------------------------------
Promise — объект, представляющий eventual completion (или failure) асинхронной операции и её результат.

Как работает:
- Promise создаётся конструктором new Promise((resolve, reject) => { ... }), где внутри выполняется асинхронная работа, и по её завершении вызывается resolve(value) или reject(error).
- У промиса есть метод then(onFulfilled, onRejected) и catch(onRejected), finally(onFinally). then возвращает новый промис, что позволяет цепочки.

Состояния (три основных):
1) pending — начальное состояние, промис не завершён.
2) fulfilled (resolved) — операция успешно завершена; хранится значение.
3) rejected — операция завершилась ошибкой; хранится причина (ошибка).

Особенности:
- Промис может переходить состояние только один раз: из pending в fulfilled или rejected.
- then/catch могут быть вызваны уже после разрешения промиса — обработчики всё равно выполнятся асинхронно.

Альтернативы для обработки асинхронного кода:
- Колбэки (callback) — традиционный способ, но приводит к «callback hell».
- async/await — синтаксический сахар поверх промисов: позволяет писать асинхронный код, выглядящий как синхронный. (async function f() { const res = await fetch(...); })
- Observable (RxJS) — для потоков значений (мульти-эмиссий).
- Event-driven (события) — через события и слушатели.
- Web Workers / Message passing — для параллельных задач.

Роль Event Loop:
- Event Loop — это механизм, который обеспечивает асинхронность в однопоточном JS: он обрабатывает стек вызовов (call stack) и очередь (task queue / microtask queue).
- Когда выполняется асинхронная операция (setTimeout, fetch, промисы), соответствующие колбэки ставятся в очереди: обычные задачи (macrotasks: setTimeout, setInterval, I/O) и микрозадачи (microtasks: Promise.then, queueMicrotask).
- После выполнения текущего стека событий event loop опустошает microtask queue (выполняет все микрозадачи), затем берет одну macrotask и так далее.
- Это объясняет поведение: .then промисов выполняется раньше, чем setTimeout(..., 0), потому что then попадает в microtask и выполняется до следующей macrotask.

Пример:
Promise.resolve().then(() => console.log('microtask'));
setTimeout(() => console.log('macrotask'), 0);
// Результат: 'microtask' затем 'macrotask'

3. ООП и его реализация в JavaScript
-----------------------------------
Что такое ООП:
Объектно-ориентированное программирование — парадигма, где моделируемая система строится вокруг объектов, взаимодействующих друг с другом. Ключевые принципы:
1) Инкапсуляция — объединение данных (состояния) и методов, которые их изменяют, и скрытие внутренней реализации.
2) Наследование — возможность создавать новые классы/объекты на основе существующих, унаследовав свойства и поведение.
3) Полиморфизм — объекты разных типов могут быть использованы через единый интерфейс; поведение определяется конкретной реализацией.
4) Абстракция — выделение существенных характеристик объекта, скрывая ненужные детали.

Примеры:
- Класс Animal с методом makeSound(); Dog наследует Animal и реализует makeSound().
- Интерфейс/контракт: метод render() для компонентов.

Как ООП реализовано в JavaScript:
- До ES6: прототипное наследование. Объекты наследуют свойства через цепочку прототипов (prototype).
  Пример:
    function Animal(name) {
      this.name = name;
    }
    Animal.prototype.say = function() { console.log(this.name); };

    function Dog(name) {
      Animal.call(this, name);
    }
    Dog.prototype = Object.create(Animal.prototype);
    Dog.prototype.constructor = Dog;
- ES6 class — синтаксический сахар над прототипами:
    class Animal {
      constructor(name) { this.name = name; }
      say() { console.log(this.name); }
    }
    class Dog extends Animal {
      bark() { console.log('woof'); }
    }
  При этом под капотом всё те же прототипы и методы на прототипе.
- Инкапсуляция:
  - Публичные свойства/методы: обычные поля и методы класса.
  - Приватные поля: с ES2020 можно использовать `#`-префикс: `#secret`. Доступ к ним возможен только внутри класса.
  - Символы (Symbol) и замыкания — альтернативные способы скрытия данных.
- Полиморфизм:
  - Переопределение методов в подклассах, использование общих интерфейсов.
- Композиция vs наследование:
  - В JS часто предпочитают композицию (объекты получают поведение через включение компонентов), особенно чтобы избежать глубоких иерархий.

Пример класса с приватным полем:
  class Counter {
    #count = 0;
    increment() { this.#count++; }
    get value() { return this.#count; }
  }

Отличия JS-ООП от классического (например, Java/C#):
- Прототипная модель: объекты наследуют от объектов, а не от классов.
- Динамическая типизация и возможность менять прототипы/методы во время выполнения.
- Отсутствие строгих интерфейсов (есть TypeScript для типизации).
- Функции первого класса и замыкания дают гибкие способы реализации инкапсуляции.

4. Как браузер обрабатывает URL — подробно
------------------------------------------
1) Ввод URL и разбор:
- Пользователь вводит URL в адресную строку. Браузер парсит схему (protocol), хост, порт (если указан), путь, строку запроса и хеш.
  Пример: https://example.com:443/path?query=1#frag
- Если введено неполное: браузер может выполнить поиск через поисковую систему.

2) Проверка кэша/Service Worker:
- Браузер проверяет локальный кэш (HTTP cache) и Service Worker (если зарегистрирован и соответствующий scope). Service Worker может перехватить запрос и вернуть ответ из кэша или из собственного кода.

3) DNS-резолвинг:
- Браузер запрашивает IP-адрес домена. Сначала проверяются локальные записи (hosts), затем кэш DNS ОС/браузера, потом do DNS lookup к DNS-серверам.
- DNS-over-HTTPS/DNS-over-TLS может использоваться для приватности.

4) Установка соединения:
- Для HTTPS: TLS handshake (установка защищённого канала). Включает проверку сертификата (CA chain), проверку даты/отзыва и т.п.
- Происходит TCP handshake (SYN/SYN-ACK/ACK) и затем TLS handshake поверх TCP.

5) HTTP-запрос:
- Браузер формирует HTTP-запрос (GET/POST и т.д.), добавляет заголовки (User-Agent, Accept, Accept-Encoding, Host, Cookie, Referer и др.).
- Если есть кросс-доменные ресурсы, отправляются CORS-заголовки (Origin).

6) Серверный ответ:
- Сервер отвечает статус-кодом и заголовками (Content-Type, Cache-Control, Set-Cookie, CORS headers).
- Браузер обрабатывает заголовки: управляет кэшированием, перенаправлениями (3xx), куками, разрешениями и пр.

7) Загрузка ресурсов:
- После получения HTML документ парсится. Парсер идёт по HTML, строит DOM. Когда встречаются теги <link rel="stylesheet"> и <script>, поведение зависит от атрибутов:
  - CSS: блокирует рендер пока не загружен и проанализирован (CSSOM).
  - Скрипты без async/defer блокируют парсинг HTML; async загружается и выполняется, когда готов; defer ждет до конца парсинга.
- Одновременно браузер запускает загрузку других ресурсов: изображения, шрифты, CSS, JS, XHR/fetch (в зависимости от приоритетов и ограничений соединений).
- Формируется дерево рендеринга: DOM + CSSOM -> Render Tree.

8) Layout и Paint:
- Layout (reflow): вычисление позиций и размеров элементов.
- Paint: отрисовка пикселей на слоях (compositing).
- Compositing: объединение слоёв GPU и вывод на экран.

9) Выполнение скриптов и событий:
- JS выполняется в главном потоке (если не используются web workers). Скрипты могут манипулировать DOM, вызывать дополнительные загрузки, изменять стили и т.д. Это может вызвать reflow/ repaint.
- После первого рендеринга браузер продолжает загружать и применять ресурсы, запускать JS, обрабатывать события.

Технологии, ускоряющие процесс:
- Кэширование (HTTP cache, Service Workers, localStorage/IndexedDB для ресурсов).
- CDN (сокращает латентность, физически ближе к пользователю).
- HTTP/2 и HTTP/3 (QUIC) — мультиплексирование запросов, снижение накладных расходов на соединение.
- Gzip/Brotli сжатие.
- Минификация и бандлинг (уменьшает размер и количество запросов) — но с HTTP/2 меньше смысла в агрессивном бандлинге.
- Prefetch, Preconnect, DNS-prefetch, Preload — подсказки браузеру загружать ресурсы заранее.
- Lazy loading изображений/видео.
- Использование критического CSS (inline critical CSS) и отложенной подгрузки неважного CSS.
- Оптимизации рендера: GPU-ускорение, использование will-change, избегание layout-thrashing.
- Server-Side Rendering (SSR) / Static Site Generation (SSG) — уменьшает время до первого полезного контента (TTFB -> First Contentful Paint).
- Использование HTTP caching headers (Cache-Control, ETag, Last-Modified).

Возможные проблемы и вопросы безопасности:
- HTTPS / SSL/TLS: неправильная настройка сертификатов ведёт к предупреждениям/блокировкам.
- Mixed Content: страница по HTTPS, ресурсы по HTTP — браузер может блокировать.
- CORS (Cross-Origin Resource Sharing): ограничивает доступ из JS к ресурсам других доменов; требует корректных заголовков Access-Control-Allow-Origin на сервере.
- CSRF (Cross-Site Request Forgery): может потребовать защиту (CSRF-токены, SameSite cookie).
- XSS (Cross-Site Scripting): внедрение скриптов через уязвимости; требует экранирование и Content Security Policy (CSP).
- Clickjacking: защита через X-Frame-Options или CSP frame-ancestors.
- Протоколы безопасности: HSTS (Strict-Transport-Security) принуждает HTTPS.
- CORS preflight (OPTIONS) добавляет накладные расходы.
- Разделение контента между доменами: sandboxing (iframe sandbox), postMessage — безопасный обмен между окнами/iframe.
- Cookies: атрибуты Secure, HttpOnly, SameSite важны для безопасности.

Заключение:
Путь от ввода URL до рендера — это цепочка сетевых операций, политики кэширования, парсинга и рендеринга. Оптимизации включают сетевые (CDN, HTTP/2/3), кэширование, предзагрузку ресурсов и рендер-ориентированные техники; проблемы — это в основном сетевые и междоменные политики безопасности.
